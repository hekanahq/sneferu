# 1. Getting started

Sneferu is the language and SDK for Hekana store themes. A theme is a folder of
HTML-like `.snf` templates with `hk-*` tags, a `theme.json` manifest, locale
files and CSS. The CLI checks it, previews it with sample data and compiles it to
one JSON artifact that Hekana renders.

## Prerequisites

| Need | Version |
| - | - |
| Node.js | 20 or newer (`node -v`) |
| An editor | any; `.snf` files are HTML, so HTML highlighting works. [Format your theme](10-format-your-theme.mdx) sets up Prettier and format on save |

## Create a theme

```bash
npx sneferu init my-theme
cd my-theme
```

`init` copies the starter theme into `my-theme/` and sets `theme.json` `id` from
the folder name (`my-theme`) and `name` to its title case (`My Theme`). It refuses a non-empty folder unless you pass
`--force`.

<Callout kind="note">
  To skip `npx`, install the CLI once: `npm i -g sneferu`. It is then
  available as `sneferu` (or the short `snf`), for example `sneferu dev my-theme`.
  `npm create sneferu my-theme` does the same as `npx sneferu init my-theme`.
  `sneferu` is a short name for the `@hekana/sneferu` package; both install the same tool.
</Callout>

<Example>

```bash
npx sneferu dev            # current folder
npx sneferu dev ./my-theme --port 4200
```

Open `http://127.0.0.1:4100`. A new theme looks like the picture: the starter's
hero section and a grid of sample products, in English, left to right.

| What | Detail |
| - | - |
| Address | `http://127.0.0.1:4100` (local only; `--port` changes the port) |
| Language | The theme's `defaultLocale`. `?locale=<code>` shows another locale the theme lists in `locales` |
| Other templates | `http://127.0.0.1:4100/__template/<name>` renders `templates/<name>.snf` |
| Live reload | Saving any file recompiles and reloads the open page |
| Errors | A theme that does not compile shows the diagnostics list instead of the page |
| CSS | Every `assets/*.css` file (top level of `assets/`) is inlined after the token variables |
| Assets | `asset_url('logo.svg')` points at `/__assets/logo.svg` |

The preview uses sample data, not a real store:

| Data | Sample value |
| - | - |
| `store.name` | `Sample store` |
| Currency | EGP, so `money` prints `EGP 520.00` |
| `collection('featured')`, `'new'`, `'gift-cards'`, `'subscriptions'` | 4 to 6 products each, with `title`, `url` (`/products/<handle>`, or `/en/products/<handle>` in English), `price` (piastres), `compare_at`, `image.url` |
| `product('sample-1')` | the first of those products |
| Theme settings | every setting at its `default` |
| Sections | the default sections listed in the template's `<hk-schema>` (see [chapter 3](03-sections-and-blocks.mdx)) |

Any other collection is empty and any other product is nothing, which is a good
way to check your empty states.

### Your own sample data

To preview with products like your store's, put a `.sneferu-dev/data.json` in
the theme folder (or pass `--data <file>`). Folders starting with a dot are never
part of the theme and are never pushed.

```json title=".sneferu-dev/data.json"
{
  "store": { "name": "Pages" },
  "collections": {
    "ebooks": {
      "title": "E-books",
      "products": [
        { "title": "Notes on design", "url": "/products/notes", "price": 9900,
          "compare_at": null, "image": { "url": "https://example.com/notes.png" } }
      ]
    }
  }
}
```

| Key | Effect |
| - | - |
| `store` | merged over the sample store, e.g. `store.name` |
| `collections` | added to the sample collections; a handle you list (even `featured`) replaces the sample one |
| `products` | added to the `product('handle')` lookups |

For different text per language, split the file by locale:
`{ "ar": { "store": … }, "en": { "store": … } }`. The file is read on every
request: save it and reload the page. A file that is not valid JSON shows an
error page naming the file.

`init` writes a complete store: a layout with header, footer and announcement
groups, a template for every page type (home, product, collection, search,
cart, page, 404), the sections, blocks and snippets they use, tokens in
`theme.json` and `assets/theme.css`. `npx sneferu init --template starter`
is the same thing (`starter` is the only template for now). Everything in it
is editable by the merchant: see [Make everything editable](19-make-everything-editable.mdx).

## Check: `validate`

```bash
npx sneferu validate
```

```
✔ theme my-theme@0.1.0 is valid
```

or, with problems, one line per diagnostic and a non-zero exit code:

```
sections/hero.snf:3:5 error SN2004 unknown property "colour" on <hk-heading>. Did you mean "color"?
✖ 1 error, 0 warnings
```

Format: `file:line:col severity CODE message`. Every code is listed in
[diagnostics.md](../diagnostics.mdx). `validate` exits `0` when valid and `1` when
not, so it can gate CI.

## Compile: `build`

```bash
npx sneferu build            # → dist/my-theme-0.1.0.sneferu.json
npx sneferu build --out out  # another output folder
```

`build` runs the same checks as `validate`, writes
`<out>/<id>-<version>.sneferu.json` (the artifact) and copies `assets/` to
`<out>/assets/`. It prints the artifact hash. You do not upload this file:
`sneferu push` sends the source and Hekana compiles it itself (see
[chapter 7](07-publishing.mdx)).

## Commands

| Command | Arguments | Options |
| - | - | - |
| `init [dir]` | folder to create, default `my-theme` | `--force` write into a non-empty folder |
| `dev [dir]` | theme folder, default `.` | `--port <n>` default `4100`; `--data <file>` sample data JSON, default `.sneferu-dev/data.json` when it exists |
| `validate [dir]` | theme folder, default `.` | |
| `build [dir]` | theme folder, default `.` | `--out <dir>` default `dist` |
| `format [dir]` | theme folder, default `.` | `--check` only report files that are not formatted and exit `1` (for CI). Formats `.snf` files, `theme.json` and `locales/` with Prettier and the Sneferu plugin; see [Format your theme](10-format-your-theme.mdx) |
| `login` | | `--api-url <url>` API to sign in to, default `https://api.hekana.com/api/v1`. Signs in through the browser and saves a developer key to `~/.config/sneferu/credentials.json`; revokes the previously saved key for the same API |
| `logout` | | revokes the saved key on Hekana and deletes the file |
| `whoami` | | prints the account, key prefix and dev store the CLI uses |
| `push [dir]` | theme folder, default `.` | `--package <slug>` required, must equal `theme.json` `id`, and not a reserved slug (`starter`, `hekana`, `default`, `admin`, `official`, `theme`, `themes`, `test`, `demo`, `preview`, and anything starting with `hekana-`); `--dev-store` also installs and publishes the version on your dev store and prints its URL. Uses the key saved by `login`, or env `HEKANA_TOKEN`; env `HEKANA_API_URL` |

`login`, `logout`, `whoami` and `push` are covered in
[Get an API key](09-get-an-api-key.mdx) and [Push and publish](07-publishing.mdx).
