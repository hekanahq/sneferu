# 17. Cart and controllers

Themes cannot ship JavaScript. The behaviour of a store (picking a variant,
adding to the cart, the cart drawer) comes from a small client runtime,
[`@hekana/sneferu-controllers`](https://www.npmjs.com/package/@hekana/sneferu-controllers),
that the platform loads. The commerce tags print the markup and a
`data-hk-controller` hook; the controllers upgrade it. With no JavaScript the
markup still works as links and plain forms.

| Tag | What it prints | Controller |
| - | - | - |
| `hk-variant-picker` | One group of radio buttons (or a select) per option | `variant-picker` |
| `hk-add-to-cart` | A form: quantity, the chosen variant, a button, a message line | `add-to-cart` |
| `hk-cart-count` | An empty live region the controller fills | `cart-count` |
| `hk-cart-items` | The cart rows, with a part named `empty` | `cart-items` |
| `hk-cart-summary` | Subtotal and checkout link | `cart-summary` |
| `hk-cart-drawer` | A `<dialog>` holding other tags | `cart-drawer` |
| `hk-product-gallery` | Images and thumbnails | `gallery` |

<Example>

```html title="blocks/product-buy.snf"
<hk-variant-picker product="{{ product }}" display="buttons" />
<hk-add-to-cart
  product="{{ product }}"
  label="{{ block.settings.label }}"
  quantity="{{ block.settings.show_quantity }}"
/>
```

### Picker styles

`hk-variant-picker` takes a `display` prop.

| `display` | Result |
| --- | --- |
| `buttons` | Text buttons (default). |
| `select` | One dropdown per option. |
| `swatches` | A 64px photo tile per value (the value's swatch photo, else a variant photo of that value), else a colour dot, else text. |
| `auto` | Follows the option style the merchant chose in the product editor: photo shows tiles, colour shows dots, dropdown shows a select, anything else shows buttons. |

```html
<hk-variant-picker product="{{ product }}" display="auto" />
```

## Rules the tags follow

- A product whose options are malformed or missing shows a flat list of variants; add to cart still adds the default variant.
- On a list card, a product with `has_variants` true and no `selected_variant` gets a link to its product page labelled by `choose-label` (default "Choose options" / «اختر»), with the same classes as the button, because adding needs a variant. Single-variant products keep the add button.
- A sold-out product (or variant) shows a disabled button with the sold out label.
- `min_quantity: 500, quantity_step: 50` starts the quantity at 500 and steps by 50; the cap is dropped when it is below the minimum.
- A product with no safe `url` gets a link to the cart page, styled as the button, instead of a form.
- A variant with no title is listed as "Option 1", "Option 2", … (the `option` text) in the flat list, never by its id.
- Prices on the page follow the variant picked (`<hk-price amount="{{ product.price }}" product="{{ product }}" />`).
- Everything printed into `data-hk-config` is JSON, escaped for the attribute.

## The cart page

`hk-cart-items` has an `empty` part: put the empty-state heading, image and
button there. It also prints a link to the cart page that is visible until the
controllers run, so a visitor whose script failed still has a way forward.

```html
<hk-cart-items>
  <hk-part name="empty">
    <h2>{{ section.settings.empty_title }}</h2>
  </hk-part>
</hk-cart-items>
<hk-cart-summary />
```

Any element can open the drawer: put `data-hk-open="cart-drawer"` on a link to
the cart page. Without JavaScript it is an ordinary link.

## Order form on the page

For a one-page store, put the order form under the product:

```html
<hk-variant-picker product="{{ product }}" />
<hk-inline-checkout product="{{ product }}" />
```

`hk-inline-checkout` shows the store's own Hekana checkout in a frame of the
same store (`/checkout/embed`), for the product and its selected variant. The
theme decides where it sits; the fields, the totals and the place-order button
stay Hekana's, and the theme cannot reach inside the frame or style it beyond
the [checkout branding](23-checkout-branding.mdx) settings.

- When the shopper picks another variant on the page, the frame switches to it
  without reloading, so what she already typed stays.
- The frame sizes itself to the form's height (between 320 and 6000 px).
- The only prop besides `product` is `label`: the form's name for screen
  readers (default "Order form" / «نموذج الطلب»).
- A product without a handle renders nothing.
- In `sneferu dev` the frame shows a grey placeholder; the real form only
  exists on a Hekana store.

## App blocks

An installed app can put a widget on a page, such as a subscribe form on the product page. A theme does not write that widget; the editor offers it as a section and the section prints `<hk-app-block>`:

```html
<hk-app-block app="customer_subscriptions" block="subscribe" product="{{ product }}" />
```

- `app` and `block` must be a pair on the platform's closed list. Any other pair prints nothing, and there is no prop that takes an address.
- The tag prints a frame of a page on the store's own domain. The theme still has no script and no form control.
- The block removes itself when the app is not installed or has nothing to show for the page (for example, a product with no plan).
- The `app-block` controller sets the frame height from the height the page reports. It accepts a message only from the store's own origin and only from that frame.
- Every theme gets one editor section per block, named `app-<app>-<block>`, shown in the editor only on the page types the block allows. A section of the same name in the theme wins, so a theme can restyle it.
- `sneferu dev` serves a placeholder for the framed page. A theme editor that previews pages itself can use `createPreviewRegistry()` (components): the same tags, with `hk-app-block` printing a still box with the block's name instead of a frame.

## Styling hooks

`sn-cart-item`, `sn-cart-item-title`, `sn-cart-item-price`, `sn-cart-item-qty`,
`sn-cart-item-remove`, `sn-cart-empty`, `sn-cart-subtotal`, `sn-vp-option`,
`sn-vp-value`, `sn-qty`, `sn-atc-button`, `sn-gallery-thumbs`. The tags also
emit the structural CSS (44 px targets, the drawer, reduced motion).

## For hosts

```ts
import { startControllers, type CartHost } from '@hekana/sneferu-controllers';
const stop = startControllers(document, host); // idempotent; call stop() to remove every listener
```

`CartHost` supplies `get()`, `add()`, `update()`, `remove()`, `subscribe()`,
`format()`, `checkoutUrl` and `t()`. The controllers make no network calls and
never compute authoritative totals; the host's cart store and the server do.

Each `CartLine` from `get()` may carry the product's quantity rules:

| Field | Meaning |
| - | - |
| `minQuantity` | The least quantity the line may have (whole number, default 1). The minus button removes the line when one more step would go below it. |
| `quantityStep` | What the plus and minus buttons add or take away (whole number, default 1). |
| `maxQuantity` | The most the line may have. The plus button is marked `aria-disabled` when one more step would pass it. |

`t(key)` returns the shopper-facing text for these keys: `add_to_cart`, `added`,
`sold_out`, `remove`, `subtotal`, `checkout`, `empty`, `quantity`, `increase`
(label of the plus button), `decrease` (label of the minus button),
`add_failed` and `close`. When `add()` returns `{ ok: false }` with a `message`,
the message is shown as text; without one, or when `add()` throws, the shopper
sees `add_failed` and the error goes to `console.warn`.
The bundle is under 4 KB gzipped, uses no `eval` and no `innerHTML`.
