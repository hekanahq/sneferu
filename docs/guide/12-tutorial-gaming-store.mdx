# 12. Tutorial: build a gaming store theme

This tutorial builds **Arcade**, the home page of a shop that sells game gift
cards, in-game currency and top-up packs as codes, from a design mockup to a
live store. It uses only the CLI and the parts of Sneferu described in the
earlier chapters. The finished theme is live at
[demo-arcade.hekana.com](https://demo-arcade.hekana.com) (Arabic) and
[demo-arcade.hekana.com/en](https://demo-arcade.hekana.com/en) (English).

This page shows the key part of each file. **Full theme on GitHub:**
[examples/themes/arcade](https://github.com/hekanahq/sneferu/tree/ce6364dd2a5e12ee813061b5acd3981b285ecf47/examples/themes/arcade),
with a longer walkthrough in its `README.md`. Every excerpt links to its whole
file. To run it yourself:

```bash
git clone --depth 1 https://github.com/hekanahq/sneferu
cd sneferu/examples/themes/arcade
npx sneferu dev
```

The mockup was generated as a design brief. Its Arabic is placeholder text, its
prices were in dollars, and its cyan-to-magenta glow becomes cyan-to-lime.

The home page template lists its sections, and seeds the repeated items (tabs,
amount chips, tiles, steps, questions) as blocks, so a fresh install shows the
whole page and the merchant can add, remove and reorder each item. The excerpt
shows the first section and its first block.

## 1. Create the theme

<Steps>
  1. `npx sneferu init arcade`, then `cd arcade`.
  2. Delete `sections/hero.snf`, `sections/featured.snf` and `blocks/`.
  3. Keep `npx sneferu dev` running in a second terminal and open
     `http://127.0.0.1:4100` (Arabic is the default locale once step 2 below is
     done; add `?locale=en` for English).
</Steps>

The store needs products and four categories with these handles:
`gift-cards`, `game-currency`, `top-ups`, `subscriptions`.

## 2. Tokens

```json title="examples/themes/arcade/theme.json (excerpt)"
  "defaultLocale": "ar",
  "locales": ["ar", "en"],
  "settings": {},
  "tokens": {
    "colors": {
      "primary": "#22D3EE",
      "secondary": "#0D141C",
      "accent": "#A3E635",
      "background": "#070A0F",
      "text": "#E6EDF3",
      "muted": "#8B98A9",
      "surface": "#0C1219",
      "line": "#1C2A36"
    },
    "layout": { "contentWidth": "1200px" },
    "fonts": {
      "heading": "Rubik",
      "body": "Rubik"
    }
  }
```

[View full file on GitHub](https://github.com/hekanahq/sneferu/blob/ce6364dd2a5e12ee813061b5acd3981b285ecf47/examples/themes/arcade/theme.json#L10-L29)

1. `defaultLocale: "ar"` makes `/` Arabic, right to left; `/en` is English.
2. `primary` is the cyan and `accent` the lime. Extra keys (`muted`,
   `surface`, `line`) become `--hk-color-muted` and so on.
3. `tokens.fonts` picks Rubik, a catalogue font with Arabic and Latin glyphs,
   for headings and body text. Hekana serves the font files and writes the
   `@font-face` rules; the theme ships no font files and no `font-family`.
4. The stylesheet builds its one gradient from the two tokens. Its first rules:

```css title="examples/themes/arcade/assets/theme.css (excerpt)"
/* Arcade: near-black ground, neon cyan + lime. Colours come from theme.json tokens. */
[data-hk-theme='arcade'] {
  --arc-cyan: var(--hk-color-primary);
  --arc-lime: var(--hk-color-accent);
  --arc-grad: linear-gradient(90deg, var(--arc-cyan), var(--arc-lime));
  --arc-glow: 0 0 0 1px rgba(34, 211, 238, 0.35), 0 0 18px rgba(34, 211, 238, 0.18);
  min-height: 100vh;
  line-height: 1.6;
  background:
    radial-gradient(900px 420px at 50% -120px, rgba(34, 211, 238, 0.12), transparent 70%),
    radial-gradient(700px 360px at 85% 30%, rgba(163, 230, 53, 0.06), transparent 70%),
    var(--hk-color-background);
}
:where([data-hk-theme='arcade'] a) { color: inherit; text-decoration: none; }
:where([data-hk-theme='arcade'] h1, [data-hk-theme='arcade'] h2, [data-hk-theme='arcade'] p) { margin: 0; }
.arc-defs { position: absolute; width: 0; height: 0; overflow: hidden; }
.ic { width: 24px; height: 24px; flex: none; }
/* Block wrappers take no room: tabs, chips, tiles and steps lay out as before. */
[data-hk-theme='arcade'] [data-hk-block] { display: contents; }
```

[View full file on GitHub](https://github.com/hekanahq/sneferu/blob/ce6364dd2a5e12ee813061b5acd3981b285ecf47/examples/themes/arcade/assets/theme.css#L1-L19)

`:where(…)` keeps the link and heading resets at zero specificity, so a single
class such as `.arc-chip` can still set its own colour. `[data-hk-block] {
display: contents; }` lets a block's wrapper `<div>` disappear from the layout,
so tabs, chips and tiles sit directly in their flex or grid row.

## 3. Words, settings and links

Internal links go through `url()`: `href="{{ url('/products') }}"` is
`/products` on an Arabic page and `/en/products` on an English one. A plain
`href="/products"` would send an English shopper to the Arabic page.
`<hk-button href="/products">` does this by itself.

## 4. Header and footer

The header and the footer are the same on every page, so they are
[section groups](18-section-groups.mdx): the layout places them, and each is
an ordinary section the merchant can edit once for the whole store.

1. The `<svg class="arc-defs">` in the layout declares one gradient,
   `arc-grad`, that every tile icon reuses through CSS.
2. `<details>` and `<summary>` are the phone menu: it opens with no
   JavaScript. CSS shows it only under 640 px. Its links are the store's menu
   (`menu(section.settings.menu)`, the `main` menu by default) and the theme's
   own links while the store has none; see [Menus](20-menus.mdx).
3. `<hk-search-form>` is the search field: a real form that sends the shopper
   to the store's search page (`/en/search` on English pages). The theme only
   styles it: `.arc-search` draws the rounded field around the input and the
   button.
4. `<hk-icon name="shopping-cart" size="24" class="ic" />` draws an icon from
   the bundled Lucide set. `class="ic"` lets the stylesheet size and colour it
   like the theme's own glyphs.
5. The cart link carries `data-hk-open="cart-drawer"`: with the controllers
   running it opens `<hk-cart-drawer>`, without them it is a plain link to the
   cart page. `<hk-cart-count />` shows the number of items (see
   [Cart and controllers](17-cart-and-controllers.mdx)).
6. `"templates": ["header"]` keeps the section in the header group; the
   `#faq` link goes through `url('/')` so it works from every page.

1. The hero takes two block types, `tab` and `chip`, and loops over its
   blocks twice: tabs into the `<nav>`, chips into the chip row. The template
   seeds five tabs and eight chips; the merchant edits, adds or removes them.
2. The first tab gets the glow from CSS
   (`.arc-tabs > [data-hk-block]:first-child .arc-tab`), so there is no
   `is-active` setting to keep in sync.
3. `url(block.settings.link)` keeps a tab's link in the page's language.
4. The amounts are whole pounds, so `money: 'whole', 'major'` reads the number
   as pounds and prints `EGP 100` / `100 ج.م`. On phones a second, plain
   number replaces it, so six chips fit in one row.
5. Below the chips, an `hk-button` with `class="arc-browse"` links to the
   gift cards, and the stylesheet draws its gradient border.

## 9. Check, preview and push

<Steps>
  1. `npx sneferu format` indents every file.
  2. `npx sneferu validate` prints `✔ theme arcade@1.3.0 is valid`.
  3. In `dev`, check `?locale=en` and a window under 640 px.
  4. Change `id` in `theme.json` to a slug of your own, then
     `npx sneferu push . --package <your-slug> --dev-store`.
</Steps>

Only the home page is rendered by the theme in this release; product, category
and cart pages use the store's regular theme.

## What to know before you build your own

The three gaming themes were first built on Sneferu 0.2 and moved to 0.3; the
list of what changed is in `examples/GAPS-gaming.md`. What is still missing:

| Limit | What the three gaming themes do |
| - | - |
| no cart tag (no cart count, no add-to-cart) | the cart is an icon link to `/cart`; "Buy" buttons link to the product page |
| no carousel and no JavaScript | menus and questions use `<details>`; the Console carousel is scroll-snap with anchor links |
| images in `assets/` are served from 0.3, but these themes bundle none | icons are `hk-icon` plus a few inline SVG glyphs, hero art is inline SVG, product art comes from products |
| the icon set has 71 icons | a glyph the set lacks (a gem, a coin) is inline SVG in `snippets/glyph.snf` |
